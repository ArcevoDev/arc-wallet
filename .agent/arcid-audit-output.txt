3. SDK LAYER = @arcevo/facet-sdk (what ArcWallet would consume)
--------------------------------------------------------------
The SDK is PUBLISHED on npm as @arcevo/facet-sdk (v1.0.1) - pure fetch,
zero framework deps, designed to be used standalone. arc-id's own
src/sdk/index.ts is a singleton wrapper around it, wiring the ArcIdClient
to the Zustand auth store for token refresh + auth-cleared handling.

Classes (all re-exported by arc-id's src/sdk/index.ts):
  ArcIdClient      - core fetch client, 401 auto-refresh (onTokenRefresh)
  AuthSdk          - login, register, MFA, passkey, magic-link, sessions,
                     password reset, step-up, change-password
  PasskeySdk       - WebAuthn passkey CRUD + registration/authentication
  VcSdk            - credentials: list/verify/issue/offer/accept/revoke,
                     verification session + presentation, status lists, DID docs
  IdentitySdk      - profile, devices, external-ids, delegations,
                     onboarding (start/get/advance), registerWalletDid
  OAuthSdk         - OAuth clients + tokens
  TenantSdk        - tenant CRUD + switch-context + policy/members/DID/keys
  BillingSdk       - get subscription
  WebhooksSdk      - webhook endpoint CRUD + test
  AuditSdk         - list audit logs
  IdpSdk           - IdP connection management

4. WALLET-SPECIFIC ENDPOINTS (Already Built)
--------------------------------------------
1. register-wallet-did.flow.ts - Identity-owned did:key registration
   - POST /identity/wallet/did
   - Input: publicKeyJwk (JWK), provider, providerWalletId
   - Output: did, didDocument, walletId, keyType
   - Flow: ArcWallet generates keypair on-device -> sends only public key ->
     ArcID encodes as did:key, builds DID document, creates Decentralized-
     Identifier + Wallet rows in 1 tx
   - Non-custodial by design: private keys never touch ArcID

2. Credential Offers (offer-credential.flow.ts)
   - POST /credentials/offers - tenant creates offer, subject accepts

3. Presentation Endpoint
   - POST /credentials/verify/session - create challenge
   - POST /credentials/verify/present - JWS-signed proof + presentation
   - Anti-replay: single-use sessions, TTL

4. Wallet model (Prisma)
   - Fields: id, identityId, provider, providerWalletId, createdAt
   - Unique constraint: [provider, providerWalletId], indexed by identityId

5. GET /credentials - IMPLEMENTED (list.route.ts + list.route.test.ts)
