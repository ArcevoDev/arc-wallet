- WebAuthn passkeys (registration + authentication)
- TOTP MFA setup/verify/recovery + step-up authentication
- Magic-link authentication
- Social login (Google, GitHub, Apple, Microsoft)
- SAML2 + OIDC federation
- SD-JWT Verifiable Credentials issue/verify/revoke with BitstringStatusList
- Presentation endpoint (challenge-response verification protocol)
- Multi-tenant CRUD with TenantPolicy enforcement (5 fields)

- Webhook delivery engine (Postgres queue, retry/backoff, dead-letter)
- Rate limiting per route (all auth-sensitive routes configured)
- JTI blocklist (Redis two-tier + DB fallback)
- KMS encryption for signing keys (AES-256-GCM)
- SSRF defense (assertSafeUrl with network-layer private-IP blocking)
- CORS restricted to configured origins
- CSRF protection (cookie sameSite lax + httpOnly + secure)
- Email via Resend (13 templates)
- SMS via Brevo (MFA codes + security alerts)
- Audit logging (40+ actions)
- CI pipeline (lint → typecheck → test → build)

3. NEEDED BEFORE PRODUCTION — ⚠️
-----------------------------------

  - Blocking for wallet developers who need to run arc-id locally
  - Fix: create docker-compose.yml with Postgres 16 + Redis 7

P0 — Missing endpoint for wallet credential listing:
  - GET /credentials returns 404 (not implemented)
  - Wallet cannot display user's credentials
  - Fix: implement GET /credentials in credentials module

P1 — Dockerfile for production:
  - No Dockerfile exists
  - deploy-api.yml deploys directly (no containerization)
  - Fix: multi-stage Dockerfile for Fastify API

P1 — Migration rollback testing:
  - No prisma:migrate-down or rollback testing
  - Risk: production migration failures are irreversible
  - Fix: add rollback testing to CI

P2 — Secrets/PII scanning:
  - No automated scan for plaintext credentials in log statements
  - No dependency scanning (trivy/snyk) in CI
  - Fix: add secret scanning + dependency scanning to CI

P2 — Integration tests against real Postgres:
  - All tests use mock DB (createMockDb)
  - No real-database integration tests
  - Risk: mock/real divergences in production
  - Fix: add integration test suite with testcontainers

P2 — Observability:
  - Zero tracing exists today
  - No P95/error-rate metrics on auth/token paths
  - No structured logging beyond Pino defaults
  - Fix: add OpenTelemetry instrumentation, request correlation IDs

P3 — Frontend still being rebuilt:
  - SDK/stores/hooks/providers complete

  - Not a blocker for wallet (wallet uses API, not admin dashboard)

4. DEPLOYMENT ARCHITECTURE RECOMMENDATION
------------------------------------------
For wallet development, I recommend:

Option A: Local Development (start here)
  - Run arc-id locally (pnpm dev:all)
  - Postgres + Redis via manual install or Docker
  - Wallet connects to localhost:4000/api/v1
  - Pros: Fast iteration, no cost, full control
  - Cons: Requires manual infra setup

Option B: Deploy arc-id as a shared dev instance
  - Deploy Fastify API to a PaaS (Railway, Fly.io, Render)
  - Managed Postgres + Redis (Upstash)
  - Configure CORS for wallet dev URLs
  - Set up CI/CD from main branch
  - Pros: Team can share one backend, closer to production
  - Cons: Ongoing cost, deployment maintenance

Option C: Production deployment (when ready)
  - Containerize with Docker
  - Deploy to Kubernetes or PaaS
  - Managed Postgres (RDS, Cloud SQL, Supabase)
  - Managed Redis (Upstash, ElastiCache)
  - Add Dockerfile + health checks + monitoring
  - Enable Phase 3+4 hardening first
