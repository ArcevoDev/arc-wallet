2. ARC-ID SDK = @arcevo/facet-sdk (what the wallet consumes)
--------------------------------------------------------------
The arc-id SDK is PUBLISHED on npm as @arcevo/facet-sdk (v1.0.1). It is
pure fetch, zero framework deps, fully React Native compatible.
arc-id's src/sdk/index.ts is a singleton wrapper re-exporting the same
classes (AuthSdk, PasskeySdk, VcSdk, IdentitySdk, OAuthSdk, TenantSdk,
BillingSdk, WebhooksSdk, AuditSdk, IdpSdk) wired to the Zustand store.

  AuthSdk (auth.sdk.ts):
    login, register, logout, me(), refresh(), listSessions,
    revokeSession, forgotPassword, resetPassword, verifyEmail, verifyMfa,
    setupMfa, confirmMfa, disableMfa, stepUp, mfaRecovery, changePassword,
    requestMagicLink, authenticateMagicLink, setUsername

  PasskeySdk (passkey.sdk.ts):
    list(), registrationOptions(), register(), authenticationOptions(),
    authenticate(), deregister()

  VcSdk (vcs.sdk.ts) - credentials:
    list()  -> GET /credentials  (IMPLEMENTED, no longer 404)
    verify(), issue(), offer(), acceptOffer(), revoke(),
    createVerificationSession(), presentForVerification(),
    getStatusList(), resolveTenantDidDoc()

  IdentitySdk (identity.sdk.ts):
    updateProfile, listDevices, deleteDevice, external IDs,
    linked accounts, delegations,
    startOnboarding(flowId), getOnboardingProgress(progressId),
    advanceOnboarding(progressId, stepId, data),
    registerWalletDid({ publicKeyJwk, provider, providerWalletId })

  OAuthSdk:     clients + tokens CRUD
  TenantSdk:    tenants CRUD, switch-context, members, policy, DID,
                signing keys, projects, onboarding flows
  BillingSdk:   getSubscription
  WebhooksSdk:  endpoint CRUD + test
  AuditSdk:     list audit logs
  IdpSdk:       IdP connection management

  NOTE: Onboarding + wallet-DID are ALREADY in the SDK. The old plan's
  'wallet needs to create the onboarding wrapper' is obsolete.

3. ONBOARDING SYSTEM (ArcID-built, wallet-consumed)
------------------------------------------------------
ArcID already has a complete onboarding architecture - the wallet doesn't
need to reimplement tracking logic, only render the frontend steps.

Backend ownership (what ArcID manages):
  - OnboardingFlow model - belongs to a Project, stores ordered steps as JSON
  - OnboardingProgress model - tracks identity's position: currentStep,
    completedSteps[], completedAt, arbitrary collected data
  - Admin CRUD routes for defining flows per project
  - User-facing routes for start/advance/get progress
  - Idempotent start - calling start() twice returns same progress row
  - Steps are loose JSON schema - frontend decides rendering per step type
  - completedAt auto-sets when all steps in the flow are done

Wallet ownership (what the wallet builds):
  - services/onboarding.ts - thin wrapper over IdentitySdk onboarding
  - app/(app)/onboarding/ - onboarding screen group with step renderers
  - components/onboarding/ - step-type renderers (info cards, forms, actions)
  - stores/onboarding-store.ts - optional, tracks which flows user has seen
  - Flow trigger - show onboarding on first launch or when new flows exist

4. AUTH STORE PATTERN (from arc-id src/store/auth.store.ts)
--------------------------------------------------------------
Zustand store - singleton pattern:
  State:  user, accessToken, refreshToken, isAuthenticated, isLoading
  Actions: setAuth, setUser, setTokens, clearAuth, setLoading
  SDK integration:
    - getAccessToken() reads from store
    - refreshToken() calls AuthSdk.refresh() (POST /oauth/token)
    - onAuthCleared() calls clearAuth + removes persisted session
  The wallet mirrors this but persists tokens via expo-secure-store
  instead of localStorage.

6. ARCHITECTURE DECISIONS
--------------------------
a) SDK Portability: @arcevo/facet-sdk is pure fetch + framework-agnostic.
   Use the npm package directly - do NOT copy SDK source into the wallet.
b) Token Storage: expo-secure-store (keychain on iOS, EncryptedShared-
   Preferences on Android). Not localStorage (web-only).
c) Auth Flow Pattern: on launch -> read secure-store -> validate me() ->
   route. Expired -> try refresh -> auth screens.
d) Architecture: Zustand (matches arc-id), RN native UI (StyleSheet,
   RN primitives). The web-only facet packages (components/auth/layout)
   are NOT usable in React Native.
e) API Base URL: http://localhost:4000/api/v1 (dev), configurable via
   EXPO_PUBLIC_API_URL.
